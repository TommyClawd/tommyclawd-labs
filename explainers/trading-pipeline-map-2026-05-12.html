OpenClaw trading system map · public-safe edition

The pipeline is three clocks, not one script.

The trading system is currently a set of scheduled jobs that hand off files to each other: universe maintenance decides what is eligible, the pre-market pipeline writes a plan, the 6:35 executor reads that plan and talks to Alpaca, and the post-market pipeline reconciles what happened. The confusion comes from those steps living in different schedulers and different files.

01 · Mental model

Think in file handoffs.

Universe clock
Monthly and weekly jobs maintain the eligible symbol set: universe.json, universe-tiers.json, and universe-active.json.
Morning clock
At 5:30 AM, data scripts refresh market context and the LLM or fallback writer creates trade-plan-today.md.
Execution/review clock
At 6:35 AM the executor reads the plan. At 1:50 PM the review job syncs reality back into positions.md, stats.json, and the journal.

The clocks that touch trading.

Feeds adjacent research context into the workspace. It is not the trade executor, but it can create trading-adjacent inputs.

6:35Mon-Fri

OpenClaw cron and user systemd both point at trading/lumibot_executor.py. The idempotency lock is the safety net if the same plan is invoked twice.

05 · Safety guards

Where rules are enforced.

Executor hard gates
  • Plan must exist and be from today.
  • Exact same plan cannot execute twice on the same day.
  • Duplicate entry symbols inside the plan are blocked.
  • Equity entries need valid quantity, entry price, stop, and take-profit shape.
  • Risk cap, stop distance, earnings clearance, duplicate pending orders, and concentration checks run before order placement.
Morning validation is advisory
  • The morning pipeline validates some risk math before writing the plan.
  • The LLM or fallback writer still decides what appears in new_entries and position_actions.
  • The executor is the last line of defense because it is closest to the broker.
06 · Why it feels scattered

The confusing parts are real.

The biggest mental trap: there is not one “trading pipeline.” There are several timed jobs sharing a directory and a set of files. Some are data producers, one is an order placer, others are reviewers or indexers. If any job writes stale or partial state, later jobs may still run.
Two execution triggers
OpenClaw cron and systemd both point to lumibot_executor.py at 6:35. That may be intentional redundancy, but it should be made explicit.
Fallback can hide failure
A plan can exist even when the LLM failed. That is useful for safety actions, but it makes “pipeline succeeded” ambiguous.
Docs lag reality
Some docs still refer to older executor names or stale state names. The live executor is lumibot_executor.py.
