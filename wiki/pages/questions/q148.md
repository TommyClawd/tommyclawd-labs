### The Question

Has anyone built counterfactual scenario modeling for SaaS spend management (Zylo, Productiv, etc.) that could be adapted for edtech rationalization?

### SaaS Rationalization: The Enterprise Analog

#### The Market
- **Zylo** (Indianapolis, ~$50M raised): SaaS management platform. Discovery → inventory → license optimization → renewal management. 2026 SaaS Management Index is their marquee data product.
- **Productiv** (Palo Alto, ~$45M raised): Now positioning as "AI Portfolio Governance." Added AI visibility and compliance agent in 2025-2026. SSO-based discovery.
- **Others:** Torii, LeanIX (SAP), Flexera, Snow Software, Apptio (IBM).

#### What They Actually Do (the rationalization workflow)

**Layer 1: Discovery**
- SSO/OAuth integration (Okta, Azure AD, Google Workspace)
- Expense system ingestion (Concur, Coupa)
- Shadow IT detection
- **EdTech parallel:** SSO logs from Clever/ClassLink, SIS enrollment data

**Layer 2: Utilization Measurement**
- Login frequency, feature adoption, active vs. provisioned licenses
- Engagement scoring (Productiv's "SaaS Intelligence")
- **EdTech parallel:** LearnPlatform's usage data, LMS engagement metrics

**Layer 3: Spend Optimization**
- License reclamation (unused seats)
- Renewal benchmarking (what others pay for the same tool)
- Duplicate app identification
- **EdTech parallel:** Identifying overlapping edtech tools, renegotiating district licenses

**Layer 4: Decision Support** ← THE GAP
- This is where SaaS tools stop and M1 starts
- Zylo/Productiv tell you: "App X has 30% utilization"
- They do NOT tell you: "If you cut App X, what happens to the outcome you care about?"

#### The Counterfactual Gap

**What SaaS tools offer:**
- Utilization data (who uses what, how often)
- Cost data (what you pay, what peers pay)
- Renewal calendars (when decisions must be made)
- Basic "rationalization recommendations" (cut apps below X% utilization)

**What they DON'T offer:**
- Outcome attribution (does this tool actually improve the thing you bought it for?)
- Counterfactual scenarios ("what happens if we cut this?")
- Portfolio interaction effects ("cutting Tool A may increase usage of Tool B")
- Causal modeling of any kind

**Why not?** Because enterprise SaaS rationalization is purely a **cost optimization** problem. The "outcome" is just "does someone use the software?" — if usage is low, cut it. The outcome IS the utilization. There's no second-order question about whether the software achieved its purpose.

#### Why Education Is Structurally Different

In enterprise SaaS: Tool utility ≈ Tool usage. If people use Slack, Slack is valuable.

In education: **Tool usage ≠ Learning outcome.** A student might use an app daily and learn nothing. A teacher might use an app rarely but at exactly the right intervention moment. The utilization-as-proxy assumption that powers the entire SaaS management industry **breaks in education** because:

1. **The user (student) didn't choose the tool** — it was assigned
2. **The outcome (learning) is measured separately** from usage
3. **Confounders dominate** — student demographics, teacher quality, curriculum alignment
4. **Time lag** — tool usage today → test scores months later

This is why LearnPlatform's utilization data alone doesn't close the decision loop (Q141) — and why no SaaS rationalization tool can be "adapted" for edtech without solving the attribution problem.

#### What DOES Transfer

1. **Discovery architecture.** SSO-based app detection (Clever/ClassLink are education's Okta). This is solved and can be borrowed directly.

2. **Renewal calendar + spend tracking.** EdTech contracts follow the same annual cycle. Zylo's renewal management UX is directly adaptable.

3. **Benchmarking.** "What do peer districts pay for the same tool?" — Zylo does this for enterprise SaaS. M1 could do it for edtech.

4. **The concept of "portfolio view."** Seeing all tools in one dashboard is valuable regardless of whether you can do attribution.

#### What M1 Must Build That Doesn't Exist Anywhere

**Counterfactual scenario modeling for tool effectiveness:**

```
Given:
  - Student cohort S used Tool T for duration D
  - Student cohort S' (matched controls) did not
  - Both took Assessment A

Model outputs:
  - Estimated causal effect of Tool T on Assessment A outcomes
  - Confidence interval
  - Moderating variables (grade level, baseline score, teacher, demographics)
  - "What if" projections: if we remove Tool T, expected outcome change = X ± Y
```

This is the PGA (Portfolio Growth Attribution) concept from the M1 research chain. No SaaS management platform has built anything like this because their domain doesn't require it. **The causal inference layer IS the M1 differentiation.**

#### Closest Analogs Outside SaaS Management

1. **Clinical trial design (pharma):** Counterfactual reasoning about treatment effects with confounders. Flatiron Health's approach (Q150) is closest.
2. **A/B testing platforms (Optimizely, LaunchDarkly):** Counterfactual comparison of treatment vs. control, but for product features, not educational outcomes.
3. **Marketing mix modeling (MMM):** Attributes revenue to marketing channels using statistical models. Closest commercial analog to what PGA would do for edtech tools.
4. **Causal inference in policy evaluation (J-PAL, IES What Works):** Rigorous counterfactual methodology, but applied to programs, not tools-within-programs.

#### The Ontology-as-Product Connection (Pattern from today's PATTERN_SCAN)

The reason SaaS rationalization tools CAN'T solve the edtech problem isn't technical — it's ontological. They measure the wrong thing (utilization) because their domain's outcome IS utilization. M1's ontology defines a different outcome (learning growth attributable to tools), which requires different measurement, different data, and different inference. **The measurement framework IS the product** — same pattern as Flatiron (Q150).
